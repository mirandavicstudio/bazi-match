## 一、算法总览

### 输入 / 输出

```
输入：两个 BaziData 对象（用户 A、用户 B 的八字全数据）
      A.wuxing_dist, A.day_master, A.nayin, A.nayin_wuxing, ...
      B.wuxing_dist, B.day_master, B.nayin, B.nayin_wuxing, ...

输出：MatchResult 对象
      total_score: float        # 0-100
      grade: str                # "天作之合" / "情投意合" / ...
      grade_stars: str          # "★★★★★" / "★★★☆☆" / ...
      dimensions: list[DimensionScore]
      interpretation: str        # 模板拼接的解读文案
```

### 算法流程

```
Step1: 计算六维度得分（并行或串行，无依赖）
  ├─ dim1 = calc_dizhi_hechong(A, B)      # 地支合冲  30%
  ├─ dim2 = calc_wuxing_complement(A, B)     # 五行互补  25%
  ├─ dim3 = calc_tiangan_he(A, B)           # 天干合    15%
  ├─ dim4 = calc_rizu_relation(A, B)        # 日主关系  15%
  ├─ dim5 = calc_nayin(A, B)                # 纳音      10%
  └─ dim6 = calc_shensha(A, B)              # 神煞      5%

Step2: 加权汇总
  total = dim1*0.30 + dim2*0.25 + dim3*0.15
        + dim4*0.15 + dim5*0.10 + dim6*0.05

Step3: 总分 → 等级映射
  grade, stars = map_grade(total)

Step4: 六维度结果 → 解读文案拼接
  interpretation = generate_interpretation(dim1, dim2, ..., total, grade)

Step5: 组装 MatchResult 返回
```

## 二、维度 1：地支合冲（权重 30%）

### 2.1 数据准备

从 `BaziData` 提取地支列表（各 4 个）：

```python
A_dizhi = [A.year_pillar[1], A.month_pillar[1],
             A.day_pillar[1], A.hour_pillar[1]]
B_dizhi = [B.year_pillar[1], B.month_pillar[1],
             B.day_pillar[1], B.hour_pillar[1]]
# 例：A = "庚辰 己卯 壬申 甲辰" → A_dizhi = ["辰","卯","申","辰"]
```

### 2.2 六合对照表

```python
DIZHI_HE = {
    ("子","丑"): "土",  ("丑","子"): "土",
    ("寅","亥"): "木",  ("亥","寅"): "木",
    ("卯","戌"): "火",  ("戌","卯"): "火",
    ("辰","酉"): "金",  ("酉","辰"): "金",
    ("巳","申"): "水",  ("申","巳"): "水",
    ("午","未"): "火",  ("未","午"): "火",
}
# 共 6 对，每对双向都要存（排序也可：每次比对前 sorted(dz_pair)）
```

### 2.3 三合局对照表

```python
SANHE_JU = [
    {"申","子","辰"},   # 水局
    {"亥","卯","未"},   # 木局
    {"寅","午","戌"},   # 火局
    {"巳","酉","丑"},   # 金局
]
```

### 2.4 六冲对照表

```python
DIZHI_CHONG = {
    ("子","午"), ("午","子"),
    ("丑","未"), ("未","丑"),
    ("寅","申"), ("申","寅"),
    ("卯","酉"), ("酉","卯"),
    ("辰","戌"), ("戌","辰"),
    ("巳","亥"), ("亥","巳"),
}
```

### 2.5 计算步骤

```
初始化：
  score = 50（基础分）
  hits_he = []        # 记录命中的合
  hits_chong = []     # 记录命中的冲
  hits_sanhe = []     # 记录命中的三合

Step1: 遍历 A_dizhi × B_dizhi（4×4 = 16 种组合）
  for a_dz in A_dizhi:
    for b_dz in B_dizhi:
      pair = tuple(sorted([a_dz, b_dz]))

      # 检查六合
      if pair in DIZHI_HE:
        if pair not in hits_he:   # 去重（A有多个子，B有多个丑 → 只算一次）
          score += 15
          hits_he.append(pair)

      # 检查六冲
      if pair in DIZHI_CHONG:
        if pair not in hits_chong:
          score -= 20
          hits_chong.append(pair)

Step2: 检查三合局
  合并 A_dizhi + B_dizhi → combined_dizhi（8 个地支）
  for ju in SANHE_JU:
      if ju.issubset(combined_dizhi):
        score += 20
        hits_sanhe.append(ju)

Step3: 分数钳制
  score = max(0, min(100, score))

返回：DimensionScore(
  name="地支合冲",
  score=score,
  detail=f"发现{len(hits_he)}组合，{len(hits_chong)}组冲，{len(hits_sanhe)}组三合局",
  hits=[f"{a}{b}合（{wuxing}）" for (a,b), wuxing in hits_he] +
        [f"{a}{b}冲" for (a,b) in hits_chong] +
        [f"三合{'水木火金'[i]}局" for i, _ in enumerate(hits_sanhe)]
)
```

### 2.6 边界情况

| 情况 | 处理 |
|------|------|
| A、B 地支完全相同（4 个全同） | 算 4×4=16 组合，但去重后只有 4 对 → 合最多 +60，冲最多 -80 |
| A、B 地支完全不同 | 无合无冲，score=50（中性） |
| 三合局中"申子辰"只出现 2 个 | 不满足 `issubset()`，不加分 |

## 三、维度 2：五行互补（权重 25%）

### 3.1 数据准备

从 `BaziData.wuxing_dist` 读取（已经是计数字典，总和 = 8）：

```python
A_dist = A.wuxing_dist   # {"金":1, "木":1, "水":1, "火":2, "土":3}
B_dist = B.wuxing_dist
```

转成占比（归一化到 0-1）：

```python
def to_ratio(dist):
    total = sum(dist.values())   # 应该是 8
    return {k: v/total for k, v in dist.items()}
```

### 3.2 互补判断标准

```
弱项：占比 < 0.15（即 8 个字中 ≤ 1 个）
旺项：占比 > 0.20（即 8 个字中 ≥ 2 个）
```

### 3.3 计算步骤

```
初始化：
  A_complement = 0    # A 对 B 的互补满足数
  B_complement = 0    # B 对 A 的互补满足数
  THEORETICAL_MAX = 10  # 5 行 × 2 方向

Step1: 计算 A 的弱项，看 B 是否旺
  for wuxing in ["金","木","水","火","土"]:
      A_weak = (A_ratio[wuxing] < 0.15)
      B_strong = (B_ratio[wuxing] > 0.20)
      if A_weak and B_strong:
        A_complement += 1

Step2: 计算 B 的弱项，看 A 是否旺
  for wuxing in ["金","木","水","火","土"]:
      B_weak = (B_ratio[wuxing] < 0.15)
      A_strong = (A_ratio[wuxing] > 0.20)
      if B_weak and A_strong:
        B_complement += 1

Step3: 计算互补得分
  score = (A_complement + B_complement) / THEORETICAL_MAX * 100

  （若 A_complement + B_complement == 0，说明无互补也无冲突 → 50 分中性）
  （若互补数少但冲突多 → 加分少，分数偏低）

Step4: 生克加成（进阶，可选）
  for wuxing in ["金","木","水","火","土"]:
      if A_weak and not B_strong:
        # A 缺，B 也不旺 → 看 B 有没有能生这个五行的
        sheng_wuxing = WUXING_SHENG[wuxing]   # 例：木的生者是水
        if B_ratio[sheng_wuxing] > 0.20:
          score += 5     # 间接互补，加少量分

返回：DimensionScore(...)
```

### 3.4 五行生克关系表

```python
WUXING_SHENG = {   # 谁生我
    "金": "土",   # 土生金
    "木": "水",   # 水生木
    "水": "金",   # 金生水
    "火": "木",   # 木生火
    "土": "火",   # 火生土
}
WUXING_KE = {     # 谁克我
    "金": "木",   # 金克木
    "木": "土",   # 木克土
    "水": "火",   # 水克火
    "火": "金",   # 火克金
    "土": "水",   # 土克水
}
```

### 3.5 边界情况

| 情况 | 处理 |
|------|------|
| A、B 五行分布完全相同 | 无互补，score ≈ 50（中性） |
| A 全金，B 全火 | 严重相克，互补数 = 0，score 低 |
| A 缺水，B 水旺 | 完美互补，+1 分 → score 高 |

用五行生克动态计算，不需要手写 25 个值：

```python
def get_rizhu_score(A_wuxing, B_wuxing):
    if A_wuxing == B_wuxing:
        return 50    # 比肩
    if WUXING_SHENG[B_wuxing] == A_wuxing:
        return 60    # 我生（A 生 B）
    if WUXING_KE[A_wuxing] == B_wuxing:
        return 70    # 我克（A 克 B）
    if WUXING_KE[B_wuxing] == A_wuxing:
        return 55    # 克我（B 克 A）
    if WUXING_SHENG[A_wuxing] == B_wuxing:
        return 75    # 生我（B 生 A）
```

### 5.3 计算步骤

```

Step2: B → A 关系分
  score_B_to_A = get_rizhu_score(B_wuxing, A_wuxing)

Step3: 取平均
  score = (score_A_to_B + score_B_to_A) / 2
```

## 八、总分汇总与等级映射

### 8.1 加权汇总

```python
def calc_total_score(dim1, dim2, dim3, dim4, dim5, dim6):
    total = (
        dim1 * 0.30 +
        dim2 * 0.25 +
        dim3 * 0.15 +
        dim4 * 0.15 +
        dim5 * 0.10 +
        dim6 * 0.05
    )
    return round(total, 1)   # 保留 1 位小数
```

### 8.2 总分 → 等级映射

```python
def map_grade(total_score):
    if total_score >= 85:
        return "天作之合", "★★★★★"
    elif total_score >= 70:
        return "情投意合", "★★★★☆"
    elif total_score >= 55:
        return "尚可相处", "★★★☆☆"
    elif total_score >= 40:
        return "需多磨合", "★★☆☆☆"
    else:
        return "相克较重", "★☆☆☆☆"
```

## 九、解读文案生成

### 9.1 模板结构

每个维度预写 3 套文案（高 / 中 / 低），根据得分选择：

### 9.3 拼接逻辑

```python
def generate_interpretation(match_result):
    parts = []

    # 1. 总评
    grade = match_result.grade
    parts.append(random.choice(GRADE_INTERPRETATIONS[grade]))

    # 2. 各维度解读
    for dim in match_result.dimensions:
        if dim.score >= 70:
            template = random.choice(INTERPRETATION_TEMPLATES[dim.name]["high"])
        elif dim.score >= 40:
            template = random.choice(INTERPRETATION_TEMPLATES[dim.name]["mid"])
        else:
            template = random.choice(INTERPRETATION_TEMPLATES[dim.name]["low"])
        # 填充模板变量（如 {hits}）
        interpreted = template.format(hits=format_hits(dim.hits))
        parts.append(f"【{dim.name}】{interpreted}")

    # 3. 建议（固定模板）
    parts.append(random.choice(SUGGESTION_TEMPLATES))

    return "\n\n".join(parts)
```

## 十二、算法性能分析

### 12.1 单次匹配耗时（预估）

| 操作 | 耗时（预估） |
|------|--------------|
| `calc_dizhi_hechong()` | ~0.05 ms（16 次循环 + 查表） |
| `calc_wuxing_complement()` | ~0.02 ms（10 次判断） |
| `calc_tiangan_he()` | ~0.03 ms（16 次循环） |
| `calc_rizhu_relation()` | ~0.01 ms（查表） |
| `calc_nayin()` | ~0.01 ms（查表） |
| `calc_shensha()` | ~0.02 ms（4 次判断） |
| **单次匹配合计** | **~0.14 ms** |

### 12.2 1W 用户全量遍历

```
10,000 次匹配 × 0.14 ms/次 = 1,400 ms ≈ 1.4 秒
```

加上 SQLite 读取（~200ms）和网络传输（~300ms），**总耗时约 2 秒**，在可接受范围内。

### 12.3 优化方向（Phase 3）

若后期数据量增大（> 5W 条），可以考虑：

1. **粗筛 + 精排**：先用纳音和五行互补粗筛出 Top 500，再做完整六维度打分
2. **并行计算**：用 `multiprocessing` 或多线程并行处理多个用户
3. **预计算维度分**：将每个用户的六维度"特征向量"预存，匹配时只做向量相似度计算（但六维度不是向量空间，此方案不一定适用）

## 十三、边界案例汇总

| 案例 | 预期行为 |
|------|---------|
| A、B 是同一人（数据库中两条相同记录） | 匹配度极高（所有维度满分或接近满分） |
| A 全阳干，B 全阴干 | 无特殊处理逻辑（阳干/阴干不在当前算法中） |
| A、B 出生日期完全相同 | 四柱完全相同 → 地支六合全中，天干五合全中 → 满分 |
| A 的日主克 B 的日主，但其他维度极好 | 总分仍可能很高（日主关系只占 15%） |
| 数据库中所有用户都是男性，用户输入女性 | 算法不筛选性别（MVP 阶段），但可以加 `gender` 筛选 |
