# 八字合盘匹配系统 — 项目总览

> 版本：v1.0 | 日期：2026-06-05 | 状态：设计方案

---

## 一、项目定位

一个 Web 应用，用户输入出生日期时间，系统从 1W 名虚拟用户库中匹配出八字合盘得分最高的用户，并展示详细合盘分析。

**核心卖点**：娱乐向、结果可视化、分享友好。

## 三、技术栈总览

| 层 | 技术选型 | 理由 |
|---|---------|------|
| **后端框架** | FastAPI | 异步高性能，自动生成 API 文档，Python 生态 |
| **八字排盘** | sxtwl（寿星天文历） | 精确处理立春、节气、子时跨日 |
| **数据库** | SQLite 3 | 1W 条数据，零配置，单文件部署 |
| **前端框架** | Vue 3（CDN） | 无需构建，单 HTML 文件搞定 |
| **UI 样式** | Tailwind CSS（CDN） | 实用优先，快速出效果 |
| **部署** | 单机运行 | 初期不需要云端部署 |

## 五、模块职责划分

| 模块 | 所属层 | 核心职责 | 关键接口 |
|------|--------|---------|---------|
| **排盘模块** | 后端 | 阳历 → 四柱八字 + 五行统计 | `get_sizhu(y, m, d, h)` → `BaziData` |
| **匹配引擎** | 后端 | 两人八字 → 六维度打分 | `calc_match(bazi_a, bazi_b)` → `MatchResult` |
| **解读生成** | 后端 | 评分维度 → 文字解读 | `generate_report(match_result)` → `str` |
| **数据访问层** | 后端 | SQLite 读写 | `get_all_users()`, `insert_user()` |
| **数据播种** | 脚本 | 生成 1W 虚拟用户 | `python seed.py` |
| **API 层** | 后端 | HTTP 接口暴露 | `POST /api/match` |
| **前端页面** | 前端 | 输入表单 + 结果展示 | — |

## 七、关键决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 八字库 | sxtwl | lunarcalendar 不能算八字；sxtwl 精确处理立春分界、节气、子时跨日 |
| 数据库 | SQLite | 1W 数据量极小，零运维成本 |
| 匹配算法 | 六维度加权打分 | 可解释、可调优、每个维度独立测试 |
| 解读生成 | 模板拼接 | 不需要 LLM，速度快，文案可控 |
| 前端方案 | 单 HTML + Vue3 CDN | 最简单，免构建，部署方便 |
| API 框架 | FastAPI | 自动文档，异步支持，Python 原生 |

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| sxtwl 时辰处理边界错误 | 子时用户八字算错 | 编写单元测试覆盖 23:00-01:00 边界 |
| 1W 用户全量遍历性能 | 响应时间 > 3s | Phase 1 可接受；Phase 3 加索引优化 |
| 合盘打分权重不直观 | 用户觉得"不准" | 做成配置文件，支持热调整 |
| 娱乐功能被当真 | 法律风险 | 页面显著位置加"仅供娱乐"免责声明 |
