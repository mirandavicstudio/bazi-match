## 四、开发顺序建议

### 第一轮：后端基础数据（P0）

1. 实现 `01-shishen.md`（十神计算）
2. 实现 `04-minggua.md`（命卦 + 生肖，可并行）

**完成后验证**：调用 `/api/match`，返回 JSON 包含 `shishen_list`、`minggua`、`shengxiao` 字段。

### 第二轮：前端核心视图（P0）

3. 实现 `02-frontend-contrast.md`（前端合盘首页 + 综合对比 Tab）

**完成后验证**：浏览器打开详情弹窗，能看到双盘并排 + 十神标注 + 综合对比表。

### 第三轮：后端增强（P1）

4. 实现 `03-pattern.md`（格局判定）

**完成后验证**：合盘详情中能看到双方格局信息。

## 五、AI 开发关键约束（必须遵守）

### ❌ AI 容易犯的错误

1. **过度完成任务**：规格没要求的功能不要加
2. **忽略已有代码**：修改前必须先读现有文件
3. **数据字段随意加**：新增字段必须同步更新所有相关文件
4. **不验证**：每次改动后必须手动验证

### ✅ AI 开发检查清单（每轮必做）

- [ ] 修改前已读取所有相关文件（不止看一眼，要读完）
- [ ] 新增/修改的每一个字段，都在后端返回 JSON 中实际存在
- [ ] 前端无控制台报错
- [ ] 不修改与当前任务无关的代码
- [ ] 改动完成后，在本地实际运行验证

## 九、给 AI 的开发指令模板

当你（或 AI）要开始开发某个模块时，可以用以下指令模板：

```
请按照 docs/tech-plan/0X-xxx.md 的技术方案，实现 [模块名]。

要求：
1. 先读完技术方案文档，理解目标和约束
2. 先读取所有相关文件（models.py、paipan.py 等），理解现有代码
3. 按"实现步骤"逐步开发，不要跳步
4. 每完成一个文件修改，立即验证无语法错误
5. 完成后，按"验收标准"逐项验证
6. 如果验收不通过，返回修改，直到全部通过

禁止：
- 不要添加规格中没有的功能
- 不要重写整个文件（只修改需要改的部分）
- 不要忽略验收标准
```

## 十、重要提醒

本文档集的目的是**让 AI 能独立完成开发**，但需要人类（你）在关键节点进行验收。

**建议的开发流程**：
1. AI 按技术方案开发一个模块
2. 你按"验收标准"逐项检查
3. 如果验收不通过，告诉 AI 哪里不对，让它修改
4. 验收通过后，进入下一个模块

**不要期待 AI 一次做对**，需要迭代 2-3 轮。
