# 技术方案：命卦（东四命/西四命）+ 生肖（P1）

> **文档用途**：供 AI 开发执行。本文档描述"做什么"和"做到什么标准"，不描述"怎么写代码"。

---

## 一、目标

在合盘详情中展示每个人的**命卦**（东四命/西四命）和**生肖**，并对两人的命卦关系、生肖关系进行解读。对标参考 App 的命卦和生肖展示。

---

## 二、技术方案（高层次）

### 2.1 命卦（八宅命卦）

**什么是命卦**：根据出生年份计算，将人分为**东四命**（坎、离、震、巽）和**西四命**（乾、坤、艮、兑）。

**合婚意义**：东四命 + 西四命 = 互补，同类型 = 相合。

**计算方法**：
- 男性：（出生年份 - 3）÷ 9，取余数，查表得卦
- 女性：（出生年份 + 3）÷ 9，取余数，查表得卦
- 注意：出生年份用农历年份；余数 0 = 离卦；男命 5 寄坤，女命 5 寄艮

### 2.2 生肖

**什么是生肖**：地支对应的动物（子=鼠、丑=牛、...、亥=猪）。

**合婚意义**：生肖关系（合、冲、刑、害）反映两人的先天关系。

**生肖关系判定**：
- 六合：子丑合、寅亥合、卯戌合、辰酉合、巳申合、午未合
- 六冲：子午冲、丑未冲、寅申冲、卯酉冲、辰戌冲、巳亥冲
- 其他关系（三合、相害）可选

### 2.3 数据结构变化

**当前**：`BaziData` 没有命卦和生肖字段。

**改造后**：`BaziData` 新增：
- `minggua: dict` — `{"gua": "乾卦", "type": "西四命"}`
- `shengxiao: str` — `"戌(狗)"`

`MatchResult` 新增（合盘关系）：
- `minggua_relation: dict` — `{"relation": "互补", "desc": "..."}`
- `shengxiao_relation: dict` — `{"relation": "合", "desc": "..."}`

## 五、AI 开发约束（禁止清单）

### ❌ 禁止做的事情

1. **禁止忽略农历年份转换**：命卦计算必须用农历年份，不能直接用公历年。如果输入是公历，需判断是否在立春之前。
2. **禁止余数 0 不处理**：能被 9 整除时余数为 0，对应卦为"离卦"，不能忽略。
3. **禁止男女命卦用同一张表**：男命 5 寄坤，女命 5 寄艮，不能混用。
4. **禁止生肖关系只返回"合/冲"**：必须返回自然语言解读（如"六合，情投意合"）。
5. **禁止地支关系表不完整**：六合、六冲至少要实现，不能只写部分。

### ✅ 必须做的事情

1. **必须完整实现命卦查表**：男命、女命各一张表，余数 1-9 对应的卦名必须完整。
2. **必须处理农历/公历转换**：用 `sxtwl` 库将公历转农历（项目已有 `sxtwl` 依赖）。
3. **必须实现命卦关系解读**：东四+东四=相合，西四+西四=相合，东四+西四=互补，必须有自然语言解读。
4. **必须前端展示**：不能只算出来不展示。
5. **必须写测试**：至少测试 2 个命卦（男/女各一）、2 个生肖关系（合/冲各一）。

## 六、常见错误（AI 容易犯）

1. **命卦计算错误**：直接用公历年，不搞农历转换。→ 解决：用 `sxtwl` 库的 `fromSolar` 获取农历年份。
2. **余数 0 处理错误**：余数 0 时返回空或报错。 → 解决：余数 0 对应卦为"离卦"，需在查表时处理。
3. **男女命卦混淆**：男命 5 寄坤，女命 5 寄艮，搞反了。→ 解决：分别硬编码两张表，不要合并。
4. **生肖关系判定错误**：如卯戌关系判断为"冲"（实际是"合"）。→ 解决：先查六合表，再查六冲表，按顺序判定。
5. **前端展示位置错误**：命卦和生肖展示在"合盘首页" Tab，而不是"综合对比" Tab。→ 解决：按验收标准，展示在综合对比 Tab。
