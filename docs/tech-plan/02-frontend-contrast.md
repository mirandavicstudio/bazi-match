# 技术方案：前端合盘对比视图（P0）

> **文档用途**：供 AI 开发执行。本文档描述"做什么"和"做到什么标准"，不描述"怎么写代码"。

---

## 一、目标

将对标 App 的合盘详情页（双盘并排 + 十神标注 + 综合对比表）实现出来。这是用户体验的核心改造，让合盘结果从"分数列表"变成"专业详情页"。

---

## 二、技术方案（高层次）

### 2.1 当前问题

**当前详情弹窗**：只有评分圆环 + 六维度分数列表 + 一段解读文字。

**目标详情页**：Tab 切换结构，包含：
- **Tab 1：合盘首页** — 双盘并排 + 十神标注 + 自然语言解读
- **Tab 2：综合对比** — 参数对比表 + 四柱对齐对比 + 五行对比

### 2.2 前端结构变化

**当前**：`index.html` 有一个详情弹窗（`id="detailModal"`），内部是固定的 HTML 结构。

**改造后**：弹窗内部改为 Tab 结构，用 Vue 的 `currentTab` 状态控制显示。

### 2.3 数据需求

前端需要后端返回以下新增数据（由 `01-shishen.md` 和其他后端模块提供）：
- `shishen_list` — 十神列表（用于双盘标注）
- `contrast_table` — 综合对比表（参数名 + A值 + B值 + 关系）
- `pillar_comparison` — 四柱对齐对比数据

## 五、AI 开发约束（禁止清单）

### ❌ 禁止做的事情

1. **禁止重写整个 `app.js`**：只新增/修改与 Tab 相关的代码，不要重构整个 Vue 实例。
2. **禁止大幅修改 CSS**：用已有的 Tailwind CSS 类，不要写新的 `style.css`（除非必要）。
3. **禁止添加额外 Tab**：只做"合盘首页"和"综合对比"两个 Tab，不要加"单盘详情"Tab（那是 P2）。
4. **禁止写死数据**：所有数据必须从后端 API 获取，不能写死在前端。
5. **禁止使用复杂图表库**：五行对比用简单的进度条或文字即可，不要引入 ECharts 等重量级库。

### ✅ 必须做的事情

1. **必须保留原有功能**：评分圆环、六维度列表、解读文案必须保留（放在"合盘首页" Tab）。
2. **必须处理数据缺失**：如果后端还没实现 `contrast_table`，前端需优雅降级（显示"暂未计算"）。
3. **必须移动端适配**：双盘并排在桌面端并排，在移动端上下排列。
4. **必须无控制台报错**：完成後，F12 控制台不能有红色错误。
5. **必须可返回**：用户能关闭弹窗，能重新打开，不能卡住。

## 六、常见错误（AI 容易犯）

1. **Tab 切换逻辑错误**：点击 Tab 按钮没反应。→ 解决：确保 `switchTab` 方法正确修改 `currentTab`，且 HTML 用 `v-if` 或 `v-show` 绑定。
2. **双盘数据混淆**：Person A 的数据显示在 Person B 的位置。→ 解决：仔细检查 Vue 模板中的数据绑定，A 用 `result.person_a`，B 用 `result.person_b`。
3. **后端字段名错误**：前端用 `shishen_list`，但后端返回 `shishenList`（驼峰）。→ 解决：前后端字段名必须一致，用下划线命名（Python 风格）。
4. **移动端布局崩坏**：桌面端正常，手机上双盘重叠。→ 解决：用 Tailwind 的响应式类（`md:flex-row flex-col`）。
5. **详情弹窗打不开**：修改 HTML 结构后，弹窗不显示了。→ 解决：每次修改后，手动测试"点击查看详情"能否打开弹窗。
