## 三、模块详细设计

### 3.1 排盘模块（`paipan.py`）

#### 职责
将用户输入的阳历出生日期时间，转换为标准四柱八字，并统计五行分布。

#### 核心函数签名（设计）

```
get_sizhu(
    year: int,
    month: int,
    day: int,
    hour: int,
    minute: int = 0
) -> BaziData
```

#### 内部处理流程

```
输入：2000, 3, 15, 14, 30
        │
        ▼
  Step1: 处理子时跨日
        若 hour ∈ [23, 0] → day += 1（sxtwl.fromSolar 用调整后日期）
        │
        ▼
  Step2: 调用 sxtwl.fromSolar() 获取 Day 对象
        │
        ▼
  Step3: 提取四柱（数字索引 → 中文映射）
        年柱：day.getYearGZ()  →  TIANGAN[tg] + DIZHI[dz]
        月柱：day.getMonthGZ()
        日柱：day.getDayGZ()（注意：子时用调整后日期）
        时柱：sxtwl.getShiGz(日干索引, 时辰索引)
        │
        ▼
  Step4: 统计五行分布
        遍历 4 柱共 8 个字，每个字映射到五行，统计计数
        │
        ▼
  Step5: 计算纳音（年柱）
        60 甲子 → 纳音对照表 → 纳音名称 + 纳音五行
        │
        ▼
  Step6: 返回 BaziData 结构
```

#### 输出数据结构（`BaziData`）

```python
class BaziData:
    year_pillar: str      # "庚辰"
    month_pillar: str     # "己卯"
    day_pillar: str       # "壬申"
    hour_pillar: str      # "甲辰"
    day_master: str       # "壬"（日干 = 日主）
    wuxing_dist: dict    # {"金":1, "木":1, "水":1, "火":2, "土":3}
    nayin: str           # "白蜡金"
    nayin_wuxing: str    # "金"
```

#### 边界处理规则

| 场景 | 处理方式 |
|------|---------|
| 23:00-01:00（子时） | 日期 +1，用次日的日柱，时柱用 `getShiGz(次日日干, 0)` |
| 立春前（约 2 月 4 日） | sxtwl 自动处理，年柱归属上一年 ✅ |
| 节气分界（月柱） | sxtwl 自动处理，`getMonthGZ()` 按节气分界 ✅ |
| 润月 | 不影响八字（八字按节气，不按农历月）✅ |

### 3.2 匹配引擎模块（`matcher.py`）

#### 职责
接收两个 `BaziData`，输出六维度打分结果和汇总总分。

#### 六维度打分详细设计

每个维度独立实现一个函数，输入两个 `BaziData`，输出 0-100 的分值。

##### 维度 1：地支合冲（权重 30%）

**数据准备**：提取 A、B 各自 4 个地支，组成列表。

**合（加分）**：
- **六合对照表**：`{"子丑":土, "寅亥":木, "卯戌":火, "辰酉":金, "巳申":水, "午未":火}`
- 遍历 A 的 4 个地支 × B 的 4 个地支 = 16 种组合
- 每命中一组六合：+15 分（最多 +90 分，但 6 组合计满分 100）

- **三合局对照表**：
  - 申子辰 → 水局
  - 亥卯未 → 木局
  - 寅午戌 → 火局
  - 巳酉丑 → 金局
- 检查 A 和 B 的地支合并后是否凑齐某个三合局
- 每凑齐一组三合：+20 分

**冲（减分）**：
- **六冲对照表**：`["子午", "丑未", "寅申", "卯酉", "辰戌", "巳亥"]`
- 每命中一组六冲：-20 分

**最终公式**：
```
基础分 = 50
总分 = clamp(基础分 + 合加分 - 冲减分, 0, 100)
```

##### 维度 2：五行互补（权重 25%）

**数据准备**：A、B 各自的 `wuxing_dist`（计数），转成占比。

**互补判断**：
```
对每种五行 w:
  A_weak = (A.wuxing_dist[w] / 8 < 0.15)   # A 缺这个五行
  B_strong = (B.wuxing_dist[w] / 8 > 0.20)  # B 这个五行旺
  
  if A_weak and B_strong:
      A_complement_score += 1
      
  同理计算 B 对 A 的互补
```

**生克加成**（进阶）：
```
若 A 缺木，B 水旺 → 水生木 → 间接互补 → 额外 +0.5 分
若 A 缺木，B 金旺 → 金克木 → 更缺 → 减 0.5 分
```

**最终公式**：
```
互补满足数 = A 对 B 互补数 + B 对 A 互补数
理论最大互补数 = 10（5 行 × 2 方向）
score = (互补满足数 / 理论最大互补数) × 100
```

##### 维度 3：天干合（权重 15%）

**五合对照表**：`{"甲己":土, "乙庚":金, "丙辛":水, "丁壬":木, "戊癸":火}`

**计算**：
```
基础分 = 50
遍历 A 的 4 天干 × B 的 4 天干 = 16 种组合
每命中一组五合：+20 分（天干合比地支合稀有，加分更慷慨）
score = clamp(基础分 + 加分, 0, 100)
```

##### 维度 4：日主关系（权重 15%）

**日主** = `day_master`（日柱天干）。

**五行生克关系**：
```
我生 = 食伤  → 60 分（付出型，但愿意付出）
我克 = 财星  → 70 分（掌控感，关系稳定）
克我 = 官杀  → 55 分（被管，可能有压力）
生我 = 印星  → 75 分（被照顾，最舒服）
同我 = 比肩  → 50 分（平等，但也易争锋）
```

**计算**：
```
A→B 关系分 = 查表(A.day_master 五行, B.day_master 五行)
B→A 关系分 = 查表(B.day_master 五行, A.day_master 五行)
score = (A→B + B→A) / 2
```

##### 维度 5：纳音五行（权重 10%）

**纳音五行关系**：
```
相生（如金生水）：80 分
同类（如金金）：60 分
相克（如金克木）：30 分
```

**计算**：
```
score = 查纳音五行关系表(A.nayin_wuxing, B.nayin_wuxing)
```

##### 维度 6：神煞加分（权重 5%）

**天乙贵人查法**（以日干查地支）：
```
甲戊 → 丑未
乙己 → 子申
丙丁 → 亥酉
庚辛 → 午寅
壬癸 → 巳卯
```

**计算**：
```
基础分 = 50
A 的天乙贵人地支，在 B 的地支中能找到 → +20
B 的天乙贵人地支，在 A 的地支中能找到 → +20
（神煞是彩蛋，总分权重低，不影响大局）
score = clamp(基础分 + 加分, 0, 100)
```

#### 总分汇总

```python
total_score = (
    dim1 * 0.30 +
    dim2 * 0.25 +
    dim3 * 0.15 +
    dim4 * 0.15 +
    dim5 * 0.10 +
    dim6 * 0.05
)
```

#### 输出数据结构（`MatchResult`）

```python
class DimensionScore:
    name: str           # "地支合冲"
    score: float        # 78.5
    detail: str         # "发现2组合，1组冲，基础分50+30-20=60"
    hits: list[str]     # ["子丑合", "寅申冲"]

class MatchResult:
    total_score: float          # 78.5
    grade: str                  # "情投意合"
    grade_stars: str           # "★★★★☆"
    dimensions: list[DimensionScore]
    interpretation: str        # 模板拼接的解读文案
```

### 3.6 API 层（`main.py`）

#### 端点设计

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/api/match` | 核心匹配接口 | `MatchRequest` | `MatchResponse` |
| GET | `/api/health` | 健康检查 | — | `{"status": "ok"}` |
| GET | `/docs` | Swagger 文档 | 自动生成 | — |

#### 请求/响应模型（`models.py`）

```python
class MatchRequest:
    birth_year: int
    birth_month: int
    birth_day: int
    birth_hour: int
    birth_minute: int = 0
    gender: str          # "男" / "女"
    top_n: int = 5       # 返回 Top-N 结果

class MatchedUser:
    id: int
    name: str
    gender: str
    birth_date: str      # "1990-05-15"
    sizhu: dict         # 四柱 + 日主 + 五行
    match_score: float
    match_grade: str
    match_dimensions: list[DimensionScore]
    interpretation: str

class MatchResponse:
    success: bool
    user_bazi: BaziData  # 当前用户的八字（用于前端展示）
    matches: list[MatchedUser]
    total_time_ms: int    # 接口耗时（用于性能监控）
```

#### 核心流程（`POST /api/match`）

```
1. 接收 MatchRequest
2. 调用 paipan.get_sizhu() → 当前用户 BaziData
3. 调用 db.get_all_users() → 全量用户列表
4. 遍历每个用户：
   a. 读取用户预存的 sizhu_json（无需重新计算）
   b. 调用 matcher.calc_match(user_bazi, matched_bazi)
   c. 得到 MatchResult
5. 按 match_score 降序排序
6. 取前 top_n 条
7. 对每条调用 interpreter.generate_interpretation()
8. 组装 MatchResponse 返回
```

## 八、性能目标

| 指标 | 目标 | 测量方法 |
